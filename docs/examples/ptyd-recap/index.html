Fixes

Restarted terminals now come back exact, with 7 kinds of lost state checked byte for byte

3 PRs, merged Oct 27 to Oct 28

What people saw

After ptyd restarted, your terminals came back subtly wrong: saved cursor positions gone, a full-screen app's second screen gone, and keys caught mid-sequence lost.

Every version 1 checkpoint was a repaint of up to about 300 KiB, so every restore went through it. A malformed saved screen could also panic ptyd on a later resize (#9).

Now

Checkpoints store the emulator's exact snapshot, old version 1 files still load, and malformed history is rejected before it replaces the terminal.

Why it happened

A terminal emulator holds more than the visible characters. It also has a saved cursor position, a second screen that full-screen apps switch to, and the unfinished tail of an escape sequence still arriving. Repainting the screen as ANSI codes and replaying them keeps only what is visible, so a restored session differed from the one that had been running.

What changed

  • 7 restore cases now match the original byte for byte after checkpoint, tail replay and resize, from REP and the inactive screen to partial UTF-8, CSI and OSC #2
  • Version 1 ANSI checkpoints still load, and stay unchanged until the next normal checkpoint replaces them #2
  • Prompt markers, colors, cursor saves and independent screen modes survive restore with phosphor v0.4.0 #3
  • A saved screen that claims history it never kept is rejected at load instead of panicking during a later resize #9

The change, in code

The idea that made it work

Ask the emulator for its state instead of describing the screen to it. phosphor v0.3.0 added a binary snapshot API, so ptyd writes Snapshot(), reads it back with RestoreSnapshot, and replays the output tail as before.

Engineering details

Checkpoint format. New checkpoints are version 2 and need ptyd v0.3.0 or later to read. The reader rejects a header and body that disagree, and keeps the daemon's uint16 geometry limits rather than the library's smaller restore defaults. #2

Prompt and editor state. phosphor v0.4.0 keeps colors, prompt markers, cursor saves and independent screen modes in the snapshot, and idle shells allocate smaller emulator rows. The outer header stays at version 2, and tests read a checkpoint written by the released library. #3

Malformed saved history. The fix lives in phosphor's reader, which now validates the structure before a snapshot can replace the terminal. ptyd adopts it with a one-line module bump; the core change carries the exact fuzz regression. #9

All 3 PRs
  • #2 Checkpoints store an exact phosphor snapshot; version 1 files still load.
  • #3 Restore keeps prompt markers, colors and screen modes; idle shells use smaller rows.
  • #9 Malformed saved history is rejected at load instead of panicking on resize.

Terminal previews: 2,858 cells of background spill before the fix, zero after

2 PRs, merged Oct 29

What people saw

Previews of Codex and Claude cut off their footers and the bottom of the input box, and pane colors bled into the gaps between panes.

A read-only check of live snapshots found 2,858 cells painted outside their panes before #24.

Now

Previews keep the last painted row in view, and every cell outside a pane border matches the frame drawn with no previews, for one through eight panes.

Why it happened

A preview copies part of a larger terminal into a small box. The old code anchored that box to the cursor, but full-screen apps draw footers below it. The row renderer also fills to the right edge of the physical screen with the current background color, which is right for a full terminal and wrong for a cropped pane.

What changed

  • 2,858 escaped cells in live snapshots before, 0 after #24
  • A new test compares every cell outside pane borders for one through eight panes, with color on and off, and failed on the old renderer #24
  • Previews include the last painted row, colored blank cells included, and say how many columns lie outside the pane #19
  • Cleanup adds a constant number of control bytes per row and keeps the existing preview storage reuse #24

The change, in code

The idea that made it work

Treat a preview as a crop with hard edges. The start row comes from what was painted, and every row ends with a reset and an erase, so later panes and the browser chrome paint over a clean background in their existing order.

Engineering details

Footers and input boxes. Sparse shells still stay near the top of the pane. Observation leaves the source process and its size alone. The same PR added rounded pane frames, colors derived from the viewing terminal and a shortcut bar with room below it. #19

Background spill. Rows that end at the physical edge keep their final cell. The live check read snapshots without attaching to or changing those terminals. #24

All 2 PRs
  • #19 Previews keep app footers in view; rounded frames and softer colors.
  • #24 Preview backgrounds stay inside their panes.

New features

Codex and Claude sessions from other tabs open in ptyd; a live check finds 5 of 5

3 PRs, merged Oct 28 to Oct 29

Before

Codex and Claude conversations started in another terminal tab were invisible to ptyd, so an agent's work lived in two places.

Now you can

Pick a running Codex or Claude conversation in ptyd and press Enter. Detaching returns to the list while the native worker keeps running.

How it works

Each agent CLI keeps its own record of which conversations are running. ptyd asks that record for an exact conversation id, then checks the worker's process identity before and after it opens a frontend, so a conversation that changed in between is declined instead of attached to the wrong worker.

What it does

  • A live check found 3 Codex and 2 Claude tabs missing from native listings; the read-only probe now finds all 5 #15
  • Import rechecks the conversation id, worker pid and process identity after the frontend starts, and closes the frontend if any changed #11
  • Codex keeps its composer background: ptyd captures the viewer's colors and answers startup color queries before anyone attaches #15
  • The launch menu starts Codex and Claude with full access, f switches to CLI settings, and R relaunches a finished agent #20

Show it

  1. Start Codex in another tab, or run /bg in a foreground Claude session.
  2. Run ptyd ls, open a group and press a to list outside agents.
  3. Select the conversation and press Enter, then type quick jk to return; the worker keeps running.
  4. Exit the agent and press R to relaunch it with its original flags.

The change, in code

The idea that made it work

The agent's own runtime is the only authority. ptyd never guesses a conversation from a window title or process name. An original tab with no exact id is listed with guidance but cannot be imported, and an incomplete or ambiguous listing declines the import.

Engineering details

Discovery and import. Codex must use its shared local daemon, foreground Claude sessions need /bg in their original tab, and stopped Claude conversations need explicit --resume. Temporary frontends expire if unclaimed and close on the last live detach. #11

Session controls and original tabs. Attached views reserve a bottom row for the session name and the jk hint, drawn from ptyd's terminal model. A frontend that fails keeps its final error screen until jk, including a crash during synchronized output. #15

Launch and relaunch. Built-in choices carry their own launch flags, custom commands keep their exact shell arguments, and restored agents keep their original flags. Input queued for the old program cannot turn into menu commands. #20

All 3 PRs
  • #11 Codex and Claude sessions from other tabs can be imported into ptyd.
  • #15 Attached views keep a session bar; discovery lists original Codex and Claude tabs.
  • #20 Agents launch with full access by default; `R` relaunches a finished one.

Persistent terminal groups replace the flat picker, and the dock lists every working key

5 PRs, merged Oct 28 to Nov 2

Before

ptyd sessions were a flat list. Seeing which needed attention meant fetching each one, and once finished work piled up the picker was hard to scan.

Now you can

Open a named group of terminals with ptyd new, ptyd ls or ptyd attach, preview and take over any of them, and press quick jk to go back from any level.

How it works

ptyd already kept terminals alive across disconnects. What was missing was a way to see them as one piece of work. A group is a saved record that holds several terminals, so a person or an agent can come back to it later, and a keyboard claim decides whose input reaches a terminal when both are there.

What it does

  • ptyd status --json and GET /overview return compact summaries, and default full-history waits allocate 66% fewer bytes in the retained-output fixture #6
  • Home-row keys: i enters a session and quick jk returns, while Escape, control and function keys pass through to the app #13
  • Agents keep their terminal ids and HTTP calls, and new /groups routes let an agent put its workers in the same group #16
  • A person's keyboard claim rejects competing automation input, and read-only observation keeps working #16
  • A test presses every dock control, and the dock wraps at 40×16, 80×24 and 120×30 instead of dropping keys #27

Show it

  1. Run ptyd new website and launch a few terminals in it.
  2. Type quick jk to leave, then run ptyd ls to see the group with a live preview.
  3. Press Enter to open the group; the dock at the bottom lists every key that works for the selection.

The change, in code

The idea that made it work

Make the dock the documentation. #27 removed the : palette, ? help and three key aliases, and every key that works for the current view is labelled with what it will do, such as a archive or a unarchive.

Engineering details

Session overview. ptyd status --watch opened a live selector with output cursors and match counts. Reclaiming oversized buffers after quiet bursts cut the tested ring's retained heap by about 20% without dropping output. #6

Home-row controls. The Ctrl-backslash shortcut is gone. Quick literal jk is reserved, so pause between the letters or use bracketed paste; key repeats and modified keys never trigger it. #13

Live work first. The default picker shows live work, groups terminals and agents, and keeps completed screens under h without restarting them. New PTYs use the viewer's display settings instead of the daemon's. #14

Groups. Existing records enter Inbox without restarting, and single-terminal commands moved under ptyd term. Rename, move, archive and close-with-confirmation work on groups. #16

Dock audit. Pressing every advertised key on a real daemon showed h and a each meant two unlabelled things, and the dock never showed r, m, x, a or h. Labels now name the action for the current selection. #27

All 5 PRs
  • #6 `ptyd status --watch` and `GET /overview` show which sessions need attention.
  • #13 Home-row Vim controls: `i` enters a session, quick `jk` returns.
  • #14 Picker focuses on live work and keeps app colors and titles.
  • #16 Persistent groups of terminals with `ptyd new`, `ptyd ls` and `ptyd attach`.
  • #27 Dock lists every working control; redundant keys removed.

Up to 8 live terminal previews in one grid, searchable by screen text and scrollback

3 PRs, merged Oct 29

Before

Checking on several agents meant opening each terminal in turn, and ptyd ls printed a table that looked empty.

Now you can

Watch up to seven pinned panes plus the selected terminal, and press / to find a session by what is on its screen or in its scrollback.

How it works

A preview is a read-only copy of a terminal's current screen. ptyd reads one atomic snapshot per terminal and paints only the cells inside its panel, so watching never resizes the program, counts as a viewer or takes the keyboard.

What it does

  • Eight-pane frames allocate about 0.60 MB of temporary memory, down from 1.56 MB, with the same output bytes #23
  • Pins went from 3 to 7 plus the selected terminal, and they persist across browser restarts #18, #23
  • Search reads screens and retained scrollback, and labels combine Codex or Claude with the conversation title #23
  • A mouse report split right after Escape no longer interrupts Codex or lands in its draft #23
  • Previews keep colors and Unicode, while ls --plain, JSON, pipes and dumb terminals keep plain output #17

Show it

  1. Run ptyd ls and move between groups to see each one's live preview.
  2. Open a group and press v on up to seven terminals to pin them.
  3. Press / and type text from any screen to jump to that terminal.

The idea that made it work

Previews use the daemon's existing reads, so the browser and grid are a client-only update that leaves running terminals alone. The screen route gained a binary snapshot format so custom palettes and Unicode modes reach the preview intact.

Engineering details

Group browser. Moving between groups shows their terminals and a colored preview before entering; smaller windows stack the preview below the list. Empty workspaces explain how to start and where saved Inbox terminals are. #17

Back and pins. Quick jk goes back through menus and prompts too, and late responses cannot take the keyboard after you leave. :motion and PTYD_REDUCED_MOTION=1 turn off the rotating header. #18

Grid, mouse and captain. Rows, panes and the bottom controls take mouse clicks. Preview scratch storage and HTTP connections are reused, search matches are indexed, and hidden polling pauses during attachment. #23

All 3 PRs
  • #17 `ptyd ls` opens a group browser with colored live previews.
  • #18 Quick `jk` goes back from every level; `v` pins up to three live panes.
  • #23 Searchable grid of up to eight live previews, with mouse support.

Improvements

Scrolling an attached Codex or Claude session: 16.7 ms to paint before, 0.15 ms now

2 PRs, merged Oct 29

Before

Scrolling Codex or Claude through ptyd lagged a frame behind a direct terminal on every wheel step.

Each wheel step waited a median 16.7 ms for the next 60 Hz paint tick, and every frame resent 6,162 bytes at 120×30.

Now

Median wheel-to-paint is 0.15 ms at 120×30 and 0.21 ms at 240×64, against 0.03 to 0.06 ms for a direct PTY.

Why it happened

The attached view is a terminal drawn inside your terminal. It repainted on a fixed clock of 60 times a second, so input waited for the next tick, and it resent rows the app had redrawn without changing them. The daemon also batched output for throughput, which held back the redraw that a keypress caused.

What changed

  • 16.7 ms to 4.5 ms median by painting input responses at once and batching background output at 120 Hz #21
  • 4.5 ms to 0.15 to 0.21 ms once the daemon gives output after input a short priority window #22
  • Bytes per frame: 6,162 to 385 at 120×30, and 21,242 to 729 at 240×64 #21
  • Snapshot setup for 2,000 history rows on a loaded screen: 139 µs to 22.1 µs, with 76% fewer bytes #22

The change, in code

The idea that made it work

Paint on demand instead of on a clock. Rows are compared as exact rendered bytes, so when the app scrolls, ptyd tells the host terminal to scroll and paints only the newly exposed rows.

Engineering details

Client renderer. Idle panes have no paint timer. Row comparisons cover both scroll directions, styled blanks, links, Unicode, palettes, screen switches, restore, resize and the status row. Parse and render time per frame fell 32 to 38%. #21

Daemon priority and rollout. A client-only install gives running sessions the new renderer; the daemon change takes effect at its next safe restart. Bulk fanout showed no measured throughput change, and response chunking can add a few allocations per input. #22

All 2 PRs
  • #21 Attached scrolling paints on demand and sends only changed rows.
  • #22 Daemon prioritizes output after input; quieter status bar.

Unicode output: mixed graphemes processed 6× faster, CJK text 5× faster

1 PR, merged Oct 28

Before

Output heavy with emoji or Chinese, Japanese and Korean text moved through ptyd at 21 to 23 MB/s, against 366 to 408 MB/s for plain logs.

The emulator allocated about 154 MB of memory for every MiB of mixed Unicode output it read.

Now

Mixed graphemes run at 129 MB/s and CJK at 118 MB/s, allocating about 1.25 MB and 1.48 MB per MiB.

Why it happened

A grapheme is what a reader sees as one character, such as a flag or a family emoji, even when it is made of several code points. Finding where each one ends is expensive, and the old emulator repeated that work while formatting scrollback.

What changed

  • Mixed graphemes: 21.36 to 129.24 MB/s (6.05×) #7
  • CJK: 23.27 to 118.01 MB/s (5.07×) #7
  • Progress output: 1,311 to 1,659 MB/s (1.27×) #7
  • Allocation per MiB of mixed Unicode output: 154 MB to 1.25 MB #7

The idea that made it work

The speedup lives in phosphor, the emulator library. ptyd adopts the published release and refreshes its build profile from macOS and Linux captures, and the HTTP API and saved terminal format stay the same.

Engineering details

Method. Five alternating 200 ms samples per build ran identical ptyd code against old and new phosphor source. Claude transcripts and logs moved 1.08× and 1.03×, which needs longer measurements to call. #7

Allocations per read of Claude output: 6,153 before, 119 now, with 33% fewer bytes

2 PRs, merged Oct 27 to Nov 2

Before

Every read of Claude output made ptyd create a new string for each line, leaving thousands of small objects for Go's garbage collector.

Reading the Claude fixture made 6,153 allocations and 1,056.6 KiB of garbage per read, and about 95% of those bytes came from the line store.

Now

Retained lines share an append-only text arena, and idle terminals free unused emulator storage when their checkpoint is due.

Why it happened

ptyd keeps recent output lines so agents can fetch new output and search it. Allocating each line on its own means thousands of small objects per read, and each one is work for the garbage collector. An arena is one larger buffer that many lines are written into.

What changed

  • Allocations per op fall 97.8 to 99.7% across the ring and consume benchmarks; Consume/claude goes from 6,153 to 119 #25
  • Allocated bytes fall 18 to 33%, from 1,056.6 KiB to 708.7 KiB on Consume/claude #25
  • RingWrite is 14% faster, 752.6 µs to 647.9 µs #25
  • Idle terminals free erased rows and unused hyperlink and combining-character storage on the existing checkpoint timer #1

The change, in code

The idea that made it work

Write stripped line text once into a shared buffer and let each line point into it. Bytes below the write position never change, a full arena is replaced rather than reused, and arena sizes are powers of two so they fit the allocator's size classes.

What we tried first

Arbitrary arena sizes raised retained heap 31%. Seq-free slots cut retained heap 5.6% but made Ring.read 3× slower and search 12% slower, and a flat attacher slice showed no change. All three were reverted.

Engineering details

Line arena. Attention events clone their text because they outlive ring lines and would otherwise pin an arena. Line caps, byte budgets, snapshots and cursors behave as before, and HTTP readers showed no significant change. Retained heap per typical ring went from 752 KiB to 720 KiB. #25

Idle compaction. Compaction adds no timer and no per-output work, and keeps screen cells, retained history and unfinished parser input. The quiet check runs again before compaction and before checkpoint I/O. #1

All 2 PRs
  • #1 Idle terminals free unused emulator storage when their checkpoint is due.
  • #25 Retained line text shares one arena, cutting allocations about 98%.
